# Internationalization

The SPA's copy lives in one catalogue per language, and i18next renders it.
English ships today: the wiring, the selector, the validator and the tests are
all in place, so a second language is a directory and one array entry.

## Layout

| Path                                              | What it is                                                             |
| ------------------------------------------------- | ---------------------------------------------------------------------- |
| `apps/web/src/i18n.ts`                            | The instance, `SUPPORTED_LANGUAGES`, `normalizeLanguage`, the `t` seam |
| `apps/web/src/locales/en/translation.json`        | The copy: namespaced JSON, English is the base                         |
| `apps/web/src/useLanguage.ts`                     | The choice: read, persist, hand to i18next                             |
| `apps/web/src/components/LanguageSettingsRow.tsx` | The Settings row, offered once there is more than one language         |
| `scripts/validate-locales.ts`                     | The gate: parity, placeholders, code↔bundle coverage                   |
| `test/web/i18n.test.ts`                           | The same invariants as unit tests                                      |

## The rules

- **A visible string is Title Case; accessible-only copy lives under `a11y.*`.**
  `AGENTS.md` requires every word of user-visible text to be capitalised, and
  only accessible copy (`aria-label`, `title`, `alt`, `sr-only`, spinner labels)
  stays sentence case. `test/web/copy-style.test.ts` enforces the split by
  namespace: a key outside `a11y` must be Title Case, and the `a11y` namespace
  is the documented exemption.
- **Every call passes the English default as the second argument**
  (`t('ns.key', 'English Default')`). It keeps a missing resource readable, and
  `validate:locales` compares the default against the bundle so the two cannot
  drift into two copies of the copy.
- **A key is reached by a literal call.** The validator reads literal `t('…')`
  keys; a computed key (`t(\`${ns}.${x}\`)`) makes both coverage directions blind,
so tables of keys are written as `switch` statements returning literal calls.
- **Never write a key string inside prose.** The validator's call-site scan is a
  regex, so a doc comment quoting a key shape makes it report a missing key.
- **English values are byte-identical to the copy they replaced.** That keeps the
  suite's exact-string assertions meaningful and makes an extraction reviewable.

## Adding a language

1. Create `apps/web/src/locales/<tag>/translation.json` with exactly the keys of
   `en`, every value translated, and the same `{{placeholders}}`.
2. Add the tag to `SUPPORTED_LANGUAGES` in `apps/web/src/i18n.ts`. It must be a
   tag `@rexezuge/shared` supports; the selector takes its names from
   `LOCALE_DISPLAY_NAMES`.
3. If the language is one of the kit's, `LOCALE_NAMES` already names it.
4. Run `pnpm run validate:locales` and `pnpm test`.

The language is per device: it is stored in `localStorage`
(`pigeongram-language`) and never written to the engine, because the account's
`MeDto` has no language field. Adding one to the contract is a bridge change,
not an i18n change.

## How the check runs

`pnpm run validate:locales` calls the family's `validateLocalesCli` with this
repository's paths, so the checks are the same ones the sibling repos run:

- two-way key parity between every bundle and `en`;
- `{{placeholder}}` parity, no empty values;
- bundle directories vs. the tags `i18n.ts` declares, both directions;
- every `t('…')` key present in `en`, each inline default equal to the bundled
  value, and bundled keys no call site reaches reported as advisory.

It runs in `checks:fast` locally and as the **Locales** job in CI.

## What is not translated

Developer-facing diagnostics — the Diffie-Hellman and crypto invariant errors,
the argument checks in pure utilities — stay English, because a reader of them
is reading the code, not the product. User-facing failures are translated:
sign-in, uploads, the recorder, the clipboard, and a call's setup failures.
