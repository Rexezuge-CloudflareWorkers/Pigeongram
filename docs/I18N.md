# Internationalization

The SPA's copy lives in one catalogue per language, and i18next renders it. All
twelve locales `@rexezuge/shared` supports ship: `en`, `de`, `fr`, `es`, `it`,
`nl`, `pt`, `pl`, `ja`, `zh-CN`, `zh-TW` and `ko`. The selector, the validator
and the tests are wired to that same list.

## Layout

| Path                                              | What it is                                                             |
| ------------------------------------------------- | ---------------------------------------------------------------------- |
| `apps/web/src/i18n.ts`                            | The instance, `SUPPORTED_LANGUAGES`, `normalizeLanguage`, the `t` seam |
| `apps/web/src/locales/<tag>/translation.json`     | One catalogue per shipped language; `en` is the base                   |
| `apps/web/src/useLanguage.ts`                     | The choice: read, persist, hand to i18next                             |
| `apps/web/src/format.ts`                          | Dates, times, numbers and compact units in the chosen language         |
| `apps/web/src/components/LanguageSettingsRow.tsx` | The Settings row                                                       |
| `scripts/validate-locales.ts`                     | The gate: parity, placeholders, code↔bundle coverage                   |
| `test/web/i18n.test.ts`                           | The same invariants, plus plural and number-formatting cases           |

## The rules

- **English is Title Case; other languages use their own casing.** `AGENTS.md`
  requires every word of authored, _English_ user-visible text to be
  capitalised, and only accessible copy (`aria-label`, `title`, `alt`,
  `sr-only`, spinner labels) to stay sentence case. `test/web/copy-style.test.ts`
  reads **only the English catalogue**, so its Title Case guard does not apply
  to the other eleven. `a11y.*` is the namespace boundary there.
- **Every call passes the English default as the second argument**
  (`t('ns.key', 'English Default')`). `validate:locales` compares the default
  against the English bundle so the two cannot drift into two copies of the
  copy. This holds for toasts and failures too: the hooks that emit them call
  `t()` at the call site, and `batchResult` takes an already-translated failure
  message rather than an English noun it wraps in a template.
- **Accessible-only explanations live under `a11y.*` too.** Disabled button
  reasons, media fallback nouns (`photo`, `video`, `GIF`, `image`) and the accent
  swatch names are copy, not code: they are `t()` calls in the components that
  render them, with sentence-case values under `a11y.*`. The English values stay
  byte-identical to the strings they replaced so the component tests keep
  asserting the same names.
- **A key is reached by a literal call.** The validator reads literal `t('…')`
  keys; a computed key makes both coverage directions blind.
- **Never write a key string inside prose.** The validator's call-site scan is
  a regex, so a doc comment quoting a key shape makes it report a missing key.
- **Placeholders are byte-identical across bundles**, including i18next
  formatter tokens such as `{{count, number}}`. i18next uses `Intl.NumberFormat`
  for those and keeps numeric `count` for plural selection.
- **English values are byte-identical to the copy they replaced.** That keeps
  the suite's exact-string assertions meaningful and makes extraction
  reviewable. The one deliberate exception is grouping in large numbers,
  which locale-aware formatting introduces.

### Plurals

English used to hand-roll `commentCountOne`/`commentCount`. Plural groups now
use i18next's suffix keys: a base key plus `_one`, `_few`, `_many` and `_other`.
i18next picks the suffix with `Intl.PluralRules` for the active language —
French treats zero as singular, Polish has four forms, Japanese and both
Chinese locales have only `other`. The plain base key stays in every bundle as
a validator-visible alias: call sites name the base key, and the kit's
call-site scanner cannot resolve a suffix at runtime. All four suffixes are
present in every catalogue because the parity gate compares key sets, not
which categories a language actually uses.

When you add a plural group, keep the base and all four suffixes in **every**
catalogue and pass a numeric `count` at the call site.

### Dates and numbers

`format.ts` reads the language from i18next, never from the browser. Use its
`formatNumber`, `formatDateTime`, `formatBytes`, `formatCount` and
`formatListStamp` helpers rather than `toLocaleString()` or a hand-built unit
suffix, so a language chosen in Settings reaches every rendered number. The
`K`/`M`/`B` shorthand in `formatCount` stays Telegram-shaped; only its decimal
separator is localised.

## Adding a language

1. Create `apps/web/src/locales/<tag>/translation.json` with exactly the keys of
   `en`, every value translated, and the same `{{placeholders}}`. Use the
   language's own casing, not English Title Case.
2. Add the tag to `SUPPORTED_LANGUAGES` in `apps/web/src/i18n.ts`. It must be a
   tag `@rexezuge/shared` supports; the selector takes its names from
   `LOCALE_DISPLAY_NAMES`. The eager `import.meta.glob` picks the bundle up
   without any other wiring.
3. Add plural variants if the language needs different forms, and check that
   the format helpers render its dates and separators the way a reader expects.
4. Run `pnpm run validate:locales` and `pnpm test`.

The eleven non-English bundles were generated rather than authored by a native
speaker of each language; give them a native review before a release that leans
on them.

The language is per device: it is stored in `localStorage`
(`pigeongram-language`) and never written to the engine, because the account's
`MeDto` has no language field. Adding one to the contract is a bridge change,
not an i18n change.

## Audit status

All eleven non-English bundles were reviewed key by key in November 2026. The
pass repaired the composed login strings (the Japanese and Chinese delivery
methods doubled the particles and prepositions in `login.phaseCode`), restored
natural sentence casing in `settings.*`, `widget.*` and the extracted `a11y.*`
copy, switched CJK accessible copy to `。`, corrected Polish plural forms, and
removed terminology drift inside bundles. `validate:locales` checks shape, not
meaning, so a native review is still what keeps a generated bundle honest.

These choices need a native speaker or the owner before they change:

- `pt` is a bare tag whose bundle is mostly European Portuguese; a set of
  Brazilian values remains until the dialect is chosen (a full pt-BR bundle
  would need a new supported tag).
- `ko` mixes `Telegram` and `텔레그램`; one spelling should win.
- `es`, `it` and `pt` render Telegram's _Quiz_ as a questionnaire, and `it` and
  `pt` split `sticker` from `adesivo`.
- `pl` now uses CLDR's nominative `członkowie` for the few form; colloquial
  Polish often prefers `członka`.
- `zh-TW` still has mainland-flavoured `提交` and `加入要求`; Japanese still
  uses ASCII colons and `顔文字` for the smileys category.
- `nl` uses `reactie(s)` for both comments and reactions, and mixes two verbs
  for pinning.

## How the check runs

`pnpm run validate:locales` calls the family's `validateLocalesCli` with this
repository's paths, so the checks are the same ones the sibling repos run:

- two-way key parity between every bundle and `en`;
- `{{placeholder}}` parity, no empty values, and bundle-directory parity
  with the tags `i18n.ts` declares, both directions;
- every `t('…')` key present in `en`, each inline default equal to the bundled
  value, and bundled keys no call site reaches reported as advisory — the
  plural suffix keys are expected advisories, since i18next resolves them at
  runtime rather than through a literal call.

It runs in `checks:fast` locally and as the **Locales** job in CI.

## What is not translated

Developer-facing diagnostics — the Diffie-Hellman and crypto invariant errors,
the argument checks in pure utilities — stay English, because a reader of them
is reading the code, not the product. User-facing failures are translated:
sign-in, uploads, the recorder, the clipboard, and a call's setup failures.
